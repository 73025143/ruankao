存储系统与 Cache 平均访问时间

软考 · 计算机组成原理 ｜ 1.2.2 存储系统 ｜ 第一章最后一个"必拿计算题"（附磁盘 / 虚拟存储考点）

① 先搭楼梯：存储器的层次结构

CPU 算得飞快，但数据躺在"仓库"里。于是计算机把存储器做成 一栋楼——越往上层越快、越小、越贵。

CPU 内部寄存器最快 / 最小 / 最贵 · 纳秒级
Cache（高速缓存）比主存快 5~10 倍 · KB~MB
主存（内存）CPU 可直接访问 · GB 级
辅存（磁盘 / SSD / 光盘 / 磁带）最慢 / 最大 / 最便宜 · TB 级
↑ 速度递减、容量递增、单位价格递减 ↓
层次生活比喻跟谁交互
寄存器你正握在手里的笔CPU 内部，指令直接操作
Cache桌面上摊开的几本书与 CPU：全部由硬件实现
主存身后的书架与 Cache：硬件自动搬数据
辅存楼下的图书馆仓库与主存：硬件 + 软件（操作系统）一起实现
🔑 一句话背下来：Cache↔主存 的交互全部由硬件实现；主存↔辅存 的交互由硬件和软件结合实现。（教材原话，选择题原题出过）
🔑 为什么要分层？用"快到贵的"挡住大部分访问，用"慢到便宜的"兜底 → 速度接近 Cache，容量和价格接近辅存。

② Cache 到底解决什么问题 why cache

CPU 的速度 ≈ 0.3ns 一条指令级别 主存速度 ≈ 比 CPU 慢一两个数量级 Cache 速度 ≈ 比主存快 5 ~ 10 倍（教材原话，用快速半导体存储器做成） 所以：Cache 卡在 CPU 和主存之间，当"中转站" 目的：缓解 CPU 与主存速度不匹配（注意 ≠ 解决容量不够！）
⚠️ 最常见的一对送分题 + 送命题：
· 设置 Cache 的目的 = 缓解 CPU 与主存的速度 差异
· 设置 虚拟存储器 的目的 = 解决 主存容量 不足（让程序员写程序时不受物理内存大小限制）

为什么 Cache 真能省时间？——局部性原理

局部性含义例子
时间局部性刚访问过的，很可能马上再访问循环体里的变量 i、sum
空间局部性访问了某个地址，邻居地址也快被访问数组 a[0] a[1] a[2] 连着读；顺序执行的指令
🔑 程序运行有局部性 → 把"当前最活跃的一小撮"放进 Cache → 绝大多数访问都能命中。

教材给 Cache 的 4 个特点（概念题必背）

维度Cache 的取值
位置位于 CPU 与主存之间
容量几千字节 ~ 几兆字节（KB~MB）
速度比主存快 5~10 倍，由快速半导体存储器构成
内容主存局部域的 副本，对程序员 透明（看不见、不用管、加 Cache 不改变程序语义）
🔑 一句话：Cache 是"主存的副本"，由硬件自动管理，对程序员透明。所以程序里永远看不到"把数据存到 Cache"这种指令。

③ 主角登场：命中率与平均访问时间

先定义两个词：

命中（Hit） ：CPU 要的数据在 Cache 里 → 直接读 Cache，快 未命中（Miss）：CPU 要的数据不在 Cache 里 → 得去主存拿，慢 命中率 H = 命中次数 ÷ 总访问次数 （未命中率 = 1 − H） tc = Cache 的存取时间（命中时花的时间） tm = 主存的访问时间（未命中时要花的时间）

核心公式（模型 A：查 Cache 与查主存同时启动）

🔑 ta = H · tc + (1 − H) · tm　←　教材《软件设计师教程》主公式

为什么长这样？就是一次加权平均：

想象 100 次访问，按概率拆开： H = 0.98 → 98 次命中，每次花 tc = 1ns → 98 × 1 = 98ns 2 次未命中，每次花 tm = 10ns → 2 × 10 = 20ns 总计 118ns / 100 次 = 1.18ns ← 平均每次访问 化成公式：ta = 0.98×1 + 0.02×10 = H·tc + (1−H)·tm = 1.18ns 对比：没有 Cache 时，每次都去主存 → 平均 10ns 有了 Cache，平均只有 1.18ns → 快了约 8.5 倍
🔑 等价变形（算得快）：ta = tc + (1 − H)(tm − tc)
（命中那一下的钱 tc 是"保底"必花的，未命中时再多花 tm−tc 的差价）
⚠️ 唯一的坑：模型 B —— "不命中时才启动主存"
若 Cache 未命中后才开始访问主存（先花 tc 查 Cache，失败再花 tm 访主存），公式变成：
ta = tc + (1 − H) · tm　（同一个例子：1 + 0.02×10 = 1.2ns）
两个模型只差一次 tc；做题先看题干有没有说"同时/并行启动"。没说时按教材主公式（模型 A）算。

④ 自己调参数，看平均访问时间怎么变

命中率 H = 0.98 tc(ns) tm(ns)
🔑 拖滑条玩几下，记住这个直觉：H 越高，ta 越往下掉，但永远 ≥ tc（命中那一下的钱省不掉）。
H=100% → ta=tc；H=0% → ta=tm。

⑤ 反向考法：已知平均时间，反求命中率（变体题）

把公式当方程解，就是送分：

模型 A： ta = H·tc + (1−H)·tm = tm − H(tm − tc) 解出 H： H = (tm − ta) / (tm − tc) 例：t_a = 2ns、t_c = 1ns、t_m = 10ns H = (10 − 2) / (10 − 1) = 8/9 ≈ 0.889 → 命中率约 88.9%
💡 还有更简单的问法："要让平均访问时间不超过 2ns，命中率至少多少？"——同一道题换皮而已。
另外常考 Cache 效率 e = tc / ta（命中率越高越接近 1），以及"加速倍数 = tm / ta"。

⑦ 概念考点（不打分但必出的选择）

1) 地址映像：主存地址怎么映射到 Cache

方式规则优点 / 缺点
直接映像主存的块只能放到 Cache 中相同块号的位置（一对一）地址变换最简单 / 灵活性差（冲突多）
全相联映像主存任一块可放到 Cache 任意一块最灵活、命中率高 / 变换复杂、比较慢
组相联映像组用直接映像、组内块用全相联（前两者折中）性能与成本折中，现代 CPU 常用
🔑 记法：直接=只能回自己家；全相联=随便住；组相联=先定小区，小区里随便挑。

2) 替换算法（Cache 满了，踢谁出去）

算法踢谁备注
随机替换随机挑一个简单，效果一般
先进先出 FIFO最先进入的—
近期最少使用 LRU最近最久没用的效果好，命中率通常最高（常用）
优化替换先跑一遍程序统计后的最优选择需要先验信息，理论最优

3) 写策略（改了 Cache 里的数据怎么办）

策略做法特点
写直达 Write Through同时写 Cache 和主存简单、一致性好 / 写操作慢
写回 Write Back只写 Cache，被替换出去时才写回主存快 / 需要额外的"脏位"，一致性复杂

4) 多级 Cache

CPU 访存顺序：L1 Cache → L2 Cache → L3 Cache → 主存 · L1：离 CPU 最近、容量最小、速度最快（常常再分 指令 Cache / 数据 Cache） · L2 / L3：容量更大、速度稍慢，用来提高整体命中率 · 等级越高越靠近 CPU、越小越快 —— 别记反

⑧ 存储系统其它必考点（顺带打包）

1) 虚拟存储器（考"目的"和"置换算法"）

目的：解决主存容量不足，给程序员一个"无限大内存"的假象 原理：CPU 给虚拟地址 → MMU 地址变换 → 物理地址 → 访问主存 实现方式：页式 / 段式 / 段页式（软考默认页式） 快表 TLB：用相联存储器存页表项的副本，减少查页表的访存次数
页面置换算法规则要点
OPT 最优淘汰以后最久不会被访问的页理论最优，无法实现（作基准）
LRU 最近最少使用淘汰最久没被访问的页性能接近 OPT（OPT > LRU > FIFO）
FIFO 先进先出淘汰最早进来的页可能"加内存反而缺页更多" → Belady 异常（FIFO 独有）
⚠️ 缺页属于 程序性中断（内部异常），不是外部中断；缺页时由操作系统把该页从辅存调入主存。

2) 磁盘：容量与存取时间（大题小题都考）

容量： 格式化容量 = 面数 × (磁道数/面) × (扇区数/道) × (字节数/扇区) ← 只会用这个 非格式化容量 = 面数 × (磁道数/面) × 内圆周长 × 最大位密度 ← 教材版，偏难 存取时间： 存取时间 = 寻道时间(search) + 旋转延迟(rotational) + 数据传输时间(transfer) 平均旋转延迟 = 旋转半圈时间 = 60 / (2 × 转速rpm) 秒
例：7200 rpm 的硬盘，平均旋转延迟 = ? 转一圈 = 60/7200 s = 8.33 ms 平均（半圈）= 8.33/2 ≈ 4.17 ms 若每磁道 500 扇区、每扇区 512B，读 1 个扇区要多转？ 读数 1 个扇区 ≈ 1/500 圈 = 8.33ms / 500 ≈ 0.0167 ms
🔑 磁盘排一大半时间花在 寻道（磁臂移动）上；所以文件尽量存在同一柱面上、扇区错开排列（交替编号）都是为了少等一圈。

3) RAID（概念选择）

级别做法一句话
RAID-0条带化，无冗余最快、容量 100% / 无容错（坏一块全完）
RAID-1镜像（两块写一样的数据）可靠性最高 / 容量利用率 50%
RAID-5数据 + 分布式校验，无专用校验盘权衡之选，允许坏 1 块
RAID-6两级冗余/双重校验允许同时坏 2 块

4) 存储器分类 & SRAM / DRAM（爱考"谁做 Cache"）

分类角度类别
按位置内存（主存）／ 外存（辅存）
按材料磁存储器（磁盘、磁带）／ 半导体存储器 ／ 光存储器（光盘）
按工作方式读/写存储器 RAM ／ 只读存储器 ROM
按存取方式随机存取 RAM ／ 顺序存取（磁带）／ 直接存取（磁盘）／ 相联存取
对比SRAM 静态DRAM 动态
是否需要刷新不需要需要（电容会漏电 → 定时刷新）
速度快慢一些
集成度 / 价格低 / 贵高 / 便宜
用途Cache主存
🔑 只记一句：SRAM 做 Cache（快而贵），DRAM 做主存（便宜要刷新）。ROM 家族：固定 ROM → PROM（可编程一次）→ EPROM（紫外擦）→ EEPROM/Flash（电擦）。

⑨ 练四道（手算完再点开）

题1（主公式）：某计算机 Cache 命中率 H = 0.95，Cache 存取时间 10ns，主存访问时间 100ns。求平均访问时间（按教材主公式）。
点击看答案
ta = H·tc + (1−H)·tm = 0.95×10 + 0.05×100 = 9.5 + 5 = 14.5ns
（对比：无 Cache 时 100ns，快了约 6.9 倍）
题2（模型坑）：同题1，但题干说明"Cache 未命中时才启动主存访问"，平均访问时间是多少？
点击看答案
换成模型 B：ta = tc + (1−H)·tm = 10 + 0.05×100 = 15ns
差别就在"未命中那次要不要再花一遍 tc"——差 0.5ns。
题3（反求 H）：设 tc = 2ns、tm = 20ns，要求平均访问时间 不超过 4ns，命中率至少是多少？
点击看答案
H = (tm − ta) / (tm − tc) = (20 − 4) / (20 − 2) = 16/18 ≈ 0.889（88.9%）
验算：0.889×2 + 0.111×20 = 1.778 + 2.222 = 4ns ✓
题4（概念四连）：① 设置 Cache 的目的？② Cache 内容是谁的副本？③ Cache↔主存的交互由谁实现？④ 主存↔辅存的交互由谁实现？
点击看答案
① 缓解 CPU 与主存速度不匹配（速度差异；不是容量！）
② 主存局部域的副本，对程序员透明
③ 全部由硬件实现
④ 硬件和软件（操作系统）结合实现
题5（磁盘）：某硬盘转速 6000 rpm，平均寻道时间 8ms，每磁道 400 个扇区、每扇区 512B。求读 1 个扇区的平均存取时间。
点击看答案
① 转一圈 = 60/6000 s = 10ms；平均旋转延迟 = 10/2 = 5ms
② 传输一个扇区 = 10ms / 400 = 0.025ms
③ 平均存取时间 = 8 + 5 + 0.025 ≈ 13.03ms（寻道占大头）
